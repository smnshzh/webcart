# ربات حضور و غیاب WebKart در بله

نسخه 0.9 — نمونه قابل نصب؛ ثبت واقعی به صورت پیش‌فرض غیرفعال است.

## منطق عملیاتی
- دوره حقوق و دستمزد: ۲۱ ماه تا ۲۰ ماه بعد، حتی در تغییر سال. تاریخ امروز براساس Asia/Tehran محاسبه می‌شود. API کل دوره را می‌گیرد و تحلیل فقط تا امروز انجام می‌شود.
- ساعت مبنا 08:15 است. نخستین ورود معتبر بعد از این ساعت، مرخصی پیشنهادی از 08:15 تا همان ورود ایجاد می‌کند (مثلاً 08:39 = 24 دقیقه). کسری کل روز جایگزین این بازه نمی‌شود.
- پنجشنبه و جمعه همیشه تعطیل‌اند؛ تعطیلات رسمی و سازمانی از HOLIDAY در کارکرد WebKart خوانده می‌شوند. اگر روز هفته یا وضعیت تعطیلی نامشخص باشد، فقط هشدار داده می‌شود. تاریخ آینده بررسی نمی‌شود.
- روز کاری بدون ورود و خروج: شنبه تا سه‌شنبه 08:15 تا 17:30 (555 دقیقه)، چهارشنبه 08:15 تا 16:30 (495 دقیقه) پیشنهاد مرخصی ساعتی. برای امروز پس از پایان ساعت کاری؛ برای روزهای گذشته در همان دوره.
- اگر ورود ثبت شده ولی خروج موجود نیست و کسری مثبت است، پیام «عدم ثبت خروج، بررسی گردد» نمایش داده می‌شود و مرخصی پیشنهاد نمی‌شود. اگر فقط خروج ثبت شده، هشدار عدم ثبت ورود نمایش داده می‌شود.
- مرخصی یا مأموریت موجود و درخواست قبلی همان روز مانع پیشنهاد هستند؛ غیبت ثبت‌شده همراه با نبود هر دو تردد می‌تواند پیشنهاد مرخصی کامل ساعتی ایجاد کند. برای سایر حالت‌های غیبت بررسی دستی انجام می‌شود.
- پس از ورود، بررسی به طور خودکار شروع می‌شود؛ منوی بررسی مجدد و خلاصه کارکرد نیز موجود است. موارد پیشنهادی به صورت دکمه قابل انتخاب‌اند و فقط با تأیید نهایی ثبت می‌شوند. قبل از هر ثبت وضعیت مجدداً بررسی می‌شود. ثبت تکراری یا نتیجه نامطمئن در SQLite ثبت می‌شود و بدون بررسی دستی تکرار نمی‌شود.
- کاربر می‌تواند از منوی بله یکی از ۱۲ دوره جاری و گذشته را انتخاب کند. دوره فعال روی بررسی تأخیر، خلاصه کارکرد و وضعیت درخواست‌های مرخصی اعمال می‌شود و در متن منو نمایش داده می‌شود.

## نصب بر روی Ubuntu

```bash
cd ~/app/webkart-bot
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
nano .env
```

توکن ربات بله را در `BALE_BOT_TOKEN` قرار دهید. ورود اصلی در گفتگوی خصوصی بله انجام می‌شود: ربات ابتدا کد پرسنلی و سپس رمز را می‌گیرد و بلافاصله درخواست حذف پیام رمز را به بله می‌فرستد. اگر حذف خودکار ممکن نباشد، کاربر هشدار می‌گیرد تا پیام را دستی حذف کند. رمز و توکن نشست در دیتابیس یا لاگ ذخیره نمی‌شوند؛ نشست‌ها فقط در حافظه و برای ۶۰ دقیقه معتبرند. کاربر بعد از انقضا باید مجدداً وارد شود. پیام‌رسان ممکن است طبق سیاست خود سابقه پیام را نگه دارد.

آدرس داخلی WebKart به صورت پیش‌فرض تنظیم شده است. آدرس عمومی HTTP عمداً در کد مسدود است؛ برای اتصال از خارج شبکه VPN/HTTPS لازم است. ارتباط داخلی فعلی هم HTTP است و باید فقط در شبکه مورد اعتماد استفاده شود.

### Reverse proxy
فرم فقط روی 127.0.0.1:8797 گوش می‌دهد. نمونه Caddy (در سایت HTTPS موجود خود اضافه کنید):

```caddy
handle_path /webcart/* {
    reverse_proxy 127.0.0.1:8797
}
```

`PUBLIC_LOGIN_URL=https://YOUR-HOST/webcart` مسیر فرم HTTPS جایگزین است؛ دکمه ورود فعلی ربات اطلاعات را مستقیماً در گفتگوی خصوصی می‌گیرد. اجرای یک instance در نظر گرفته شده است.

## تنظیم APIهای نامشخص

```bash
.venv/bin/python inspect_api.py
```

این ابزار با حساب خودتان ورود می‌کند و فقط نام فیلدها و نوع داده را نمایش می‌دهد. پاسخ واقعی تردد دوره‌ای با `ioInfo/GetPersonMergeIo` و ساختار زیر تنظیم شده است:

```json
{"endpoint":"ioInfo/GetPersonMergeIo","rows_path":"Values.Table","date_field":"beginDate","entry_time_field":"BeginTime","exit_time_field":"endTime","direction_field":null,"entry_values":[],"exit_values":[],"person_field":"PERNO"}
```

رکوردهای ورود مقدار `BeginTime` و رکوردهای خروج مقدار `endTime` دارند. رکوردهای مرخصی ادغام‌شده ممکن است هر دو مقدار را داشته باشند؛ کنترل مرخصی ثبت‌شده از داده کارکرد روزانه انجام می‌شود. فقط null و رشته خالی به معنی عدم ثبت هستند و 00:00 ساعت معتبر است. ساعت مبنا در `schedule.fixed_start` برابر `08:15` است؛ ساعت پایان در `schedule.saturday_to_tuesday_end` و `schedule.wednesday_end` تنظیم شده است.

برای فعال‌سازی ثبت واقعی باید:
1. ساختار `io` روی نمونه واقعی `GetPersonMergeIo` تنظیم شده است؛ پس از هر ارتقای WebKart دوباره کنترل شود.
2. مسیر API لیست مرخصی `Vacation/PersonVacationList` و پارامترها تنظیم شده‌اند. `searchKind=5` طبق توضیح کاربر برای همه درخواست‌ها انتخاب شده؛ نمونه URL کد 7 داشت، پس این انتخاب باید روی سامانه بررسی شود. بازه همان دوره جاری و مرتب‌سازی `Desc` بر اساس `beginDate` است. پاسخ را با `inspect_api.py` بررسی کنید و `rows_path` و فیلدهای تاریخ و وضعیت را در `existing_requests` تنظیم کنید. کدهای فیلتر 1 تا 5 لزوماً کدهای وضعیت رکورد نیستند؛ کدهای رد/برگشت فقط با تأیید واقعی به `ignored_statuses` افزوده شوند. تا آن زمان ثبت واقعی غیرفعال بماند.
3. از خروجی `Vacation/GetWebVacationTypeList` مشخص کنید که شناسه 2 همان مرخصی ساعتی است؛ `leave_type.rows_path` و `id_field` را تنظیم و `confirmed_hourly` را true کنید.
4. Content-Type و متد POST برای `AddVacation` و هدرهای بعد از login را بررسی کنید. پیش‌فرض ارسال فرم URL-encoded و هدر token/username است.
5. فقط بعد از تست روی حساب مجاز، در `.env` مقدار `ENABLE_WRITES=true` را قرار دهید و سرویس را restart کنید.

تا قبل از تکمیل این موارد، ثبت واقعی مسدود است. نتیجه موفق ثبت به معنی ثبت درخواست است نه تأیید مرخصی توسط مدیر.

## اجرا و تست

```bash
.venv/bin/python -m unittest -v
.venv/bin/python bot.py
```

برای اجرای دائمی:

```bash
pm2 start bot.py --name webkart-bot --interpreter "$PWD/.venv/bin/python"
pm2 save
pm2 logs webkart-bot --lines 30
```

در بله `/start` را بفرستید و از دکمه ورود استفاده کنید. ربات تنها در گفتگوی خصوصی پاسخ می‌دهد. برای لغو جریان ورود، `/cancel` را بفرستید یا دکمه «انصراف» را بزنید.

## فایل‌ها
- `bot.py`: ورود مرحله‌ای در چت، وب‌فرم جایگزین، API Client، ربات بله و ثبت تأییدشده
- `engine.py`: منطق دوره شمسی، تأخیر و نقص تردد
- `config.json`: نگاشت ساختار API و قواعد ثبت
- `holidays.json`: تعطیلات رسمی ۱۴۰۵ و تعطیلی‌های اضافی شرکت (کاملاً آفلاین)
- `inspect_api.py`: بررسی ساختار API واقعی بدون چاپ رمز/توکن
- `test_engine.py`: ۴۲ تست واحد با داده ساختگی
- `.env.example`: تنظیمات نصب

آزمون واحد و صحت نحوی محلی انجام شده؛ ارتباط واقعی ورود با WebKart، حذف پیام رمز در بله، نگاشت پاسخ تردد و ثبت مرخصی روی سامانه سازمانی باید با یک حساب مجاز آزمایش شوند. مرز مجاز درخواست و تقویم تعطیلی خاص را سرور WebKart تعیین می‌کند. اعلان روزانه زمان‌بندی‌شده در این نسخه پیاده‌سازی نشده است.

## تغییرات نسخه 0.4 — وضعیت درخواست‌ها و مرخصی تایید نشده

- منوی ربات «وضعیت درخواست‌های مرخصی» اضافه شد؛ فیلترهای ۱ تا ۴ جداگانه از API خوانده می‌شوند و گزینه همه، وضعیت‌ها را گروه‌بندی می‌کند. این اعداد به عنوان پارامتر searchKind استفاده می‌شوند، نه به عنوان کد وضعیت خود رکورد.
- در بررسی دوره جاری، لیست همه درخواست‌ها و لیست در حال پیگیری (`searchKind=1`) جداگانه خوانده می‌شوند. اگر تاریخی در لیست در حال پیگیری باشد، پیام «مرخصی تایید نشده (در حال پیگیری)؛ ثبت مجدد انجام نمی‌شود» نمایش داده می‌شود. حتی اگر لیست همه فاقد آن تاریخ باشد، درخواست جدید ثبت نمی‌شود.
- پیش از هر ثبت واقعی، هر دو لیست مجدداً بررسی می‌شوند. اگر بررسی ناموفق باشد یا لیست ناقص تشخیص داده شود، ثبت متوقف می‌شود.
- برای منوی وضعیت، `existing_requests.rows_path`، `begin_date_field` و `end_date_field` باید مطابق Response واقعی تنظیم شوند. برای نمایش ساعت و کنترل مالک رکورد، `begin_time_field`، `end_time_field` و `person_field` نیز در صورت وجود تنظیم شوند.
- پیش‌فرض همه درخواست‌ها ۵ است؛ اختلاف با نمونه ۷ و صحت فیلترهای سرور هنوز باید بررسی شوند. اگر مجموع تعداد وضعیت‌ها با فهرست همه متفاوت باشد، ربات هشدار می‌دهد. وضعیت‌های رد و برگشت به صورت پیش‌فرض همچنان مانع پیشنهاد مجدد هستند تا کد واقعی رکوردها تأیید شود.
- این نسخه روی پاسخ‌های نمونه و آزمون محلی بررسی شده، نه روی سامانه واقعی. ثبت واقعی همچنان به صورت پیش‌فرض غیرفعال است.

## نسخه 0.5 — نگاشت پاسخ واقعی مرخصی

- پاسخ `PersonVacationList` مستقیماً در `Values` آرایه است. نگاشت `BeginDate`، `EndDate`، `BeginTime`، `EndTime`، `Status`، `StatusType`، `Name`، `Pageno`، `Type` و `IsDaily` تنظیم شد. `Status=0` درخواست جدید و `Status=10` تایید نهایی است؛ مستقل از `searchKind`.
- حتی اگر فیلتر در حال پیگیری درخواست را برنگرداند، وجود `Status=0` در فهرست همه موجب هشدار و توقف ثبت در تمام روزهای آن درخواست است. لیست در حال پیگیری نیز همچنان جداگانه دریافت می‌شود. وضعیت‌های ناشناخته از ثبت مجدد جلوگیری می‌کنند تا کد واقعی رد/برگشت مشخص شود. کنترل کل روز عمداً محافظه‌کارانه است، حتی اگر بازه‌های ساعتی متفاوت باشند.
- نمایش همه درخواست‌ها مستقیماً از فهرست همه انجام می‌شود تا رکوردهای دارای وضعیت ناشناخته حذف نشوند؛ شماره، نوع، تاریخ، ساعت و وضعیت واقعی رکورد نمایش داده می‌شود.
- نوع ۲ طبق پاسخ واقعی، استحقاقی ساعتی است؛ نوع ۱ روزانه. `confirmed_hourly=true` تنظیم شده ولی بررسی فهرست انواع مجاز در زمان ثبت همچنان فعال است و به نگاشت `leave_type.rows_path` و `id_field` نیاز دارد.
- هنوز ساختار تردد و فهرست انواع مرخصی، صحت فیلتر ۵ در برابر ۷ و نوع Content-Type برای AddVacation باید روی سامانه تأیید شوند. `ENABLE_WRITES=false` پیش‌فرض است. هیچ درخواست واقعی در آزمون‌ها ثبت نشده است.
- نمونه داده‌های واقعی پرسنلی در بسته توزیع نشده‌اند.

## نسخه 0.6 — تقویم کاری و نبود هر دو تردد

- برنامه هفتگی در `schedule.workday_ends` و `schedule.weekend` تنظیم شده است. ساعت مبنا 08:15 است؛ `DayName` و `HOLIDAY` از پاسخ کارکرد خوانده می‌شوند. تعطیلات مستقل خارج از WebKart دانلود نمی‌شوند؛ صحت تقویم سازمانی در WebKart باید بررسی شود.
- نبود تردد فقط از لیست موفق API یا فیلدهای صریح خالی استنباط می‌شود. فیلد ناموجود، داده نامعتبر یا جهت ناشناخته موجب بررسی دستی است. مقدار 00:00 همچنان ساعت معتبر در نظر گرفته شده تا معنای واقعی آن مشخص شود.

## نسخه 0.7 — ورود مستقیم در گفتگوی بله

- دکمه ورود ابتدا کد پرسنلی و سپس رمز را در گفتگوی خصوصی دریافت می‌کند؛ callbackها هرگز به عنوان رمز پردازش نمی‌شوند.
- پیام رمز قبل از درخواست ورود برای حذف به API بله فرستاده می‌شود. در صورت شکست حذف، ربات از کاربر می‌خواهد پیام را دستی حذف کند.
- رمز فقط در متغیر موقت درخواست ورود قرار می‌گیرد و در state، SQLite یا لاگ ذخیره نمی‌شود. جریان ورود پس از پنج دقیقه منقضی می‌شود و با `/cancel` قابل لغو است.

## نسخه 0.8 — انتخاب دوره گزارش

- دکمه «📅 انتخاب دوره» دوازده دوره حقوق و دستمزد اخیر را از روز ۲۱ ماه شروع تا روز ۲۰ ماه بعد نمایش می‌دهد.
- دوره انتخاب‌شده برای بررسی تأخیرها، خلاصه کارکرد و فهرست مرخصی‌ها مشترک است. با تغییر دوره، پیشنهادهای باز دوره قبلی حذف می‌شوند تا ثبت روی بازه اشتباه انجام نشود.
- بازبینی قبل از ثبت نهایی نیز با همان دوره‌ای انجام می‌شود که پیشنهادها از آن ساخته شده‌اند، حتی اگر وضعیت منو بعداً تغییر کند.

## نسخه 0.9 — تردد ادغام‌شده دوره‌ای و خطای قابل تشخیص

- دریافت تردد کل دوره از `ioInfo/GetPersonMergeIo` انجام می‌شود؛ `GetPersonIoInfo` برای بازه دوره‌ای استفاده نمی‌شود.
- نگاشت واقعی `Values.Table`، `beginDate`، `BeginTime`، `endTime` و `PERNO` فعال است و مالک تمام رکوردهای تردد با کاربر واردشده تطبیق داده می‌شود.
- خطاهای WebKart نام بخش، کد پاسخ و `Message` محدودشده سرور را نشان می‌دهند؛ `RealMessage` داخلی نمایش یا ثبت نمی‌شود.
- نوع پیشنهاد «عدم ثبت ورود و خروج» یا «تاخیر ورود» در منوی انتخاب نمایش داده می‌شود. حتی برای کل روز از نوع مرخصی استحقاقی ساعتی (2) استفاده می‌شود، نه مرخصی روزانه. ثبت نیاز به تأیید کاربر و بررسی مجدد دارد.
- ۴۲ آزمون محلی موتور و بررسی صحت نحوی موفق بوده است؛ هنوز اجرای واقعی بله و WebKart آزمایش نشده و ثبت واقعی پیش‌فرض غیرفعال است.

## نسخه 0.6 — تعطیلات و مرخصی تمام شیفت در صورت نبود تردد

- پنجشنبه/جمعه تعطیل‌اند؛ روز هفته از تاریخ شمسی با `jdatetime` محاسبه می‌شود، نه از `DayName` پاسخ API. تعطیلات رسمی ۱۴۰۵ شامل ۲۶ تاریخ از [فهرست تقویم ۱۴۰۵](https://taghvimshamsi.ir/holidays/1405/) در `holidays.json` ذخیره شده‌اند و برنامه برای کارکرد به اینترنت جهت دریافت تقویم نیاز ندارد. تاریخ تعطیلی‌های قمری و اعلامیه‌های مناسبتی ممکن است تغییر کنند؛ مدیر سامانه باید فایل را به‌روز نگه دارد.
- برای ثبت تعطیلی موردی سازمان، تاریخ مثل `1405/09/05` را در آرایه `company_closed` از `holidays.json` اضافه کنید. اگر یک سال جدید به `years` اضافه نشود، آن سال در روزهای غیر آخر هفته **Fail Closed** خواهد بود و درخواست جدید پیشنهاد نخواهد شد، حتی اگر `HOLIDAY=0` باشد.
- شنبه تا سه‌شنبه: `08:15` تا `17:30` (۹ ساعت و ۱۵ دقیقه). چهارشنبه: `08:15` تا `16:30` (۸ ساعت و ۱۵ دقیقه). این بازه طبق دستور کاربر، **مرخصی ساعتی** به API ارسال خواهد شد؛ پذیرش ۸+ ساعت مرخصی ساعتی توسط WebKart هنوز در محیط واقعی تأیید نشده و ممکن است نیاز به انتخاب مرخصی روزانه داشته باشد.
- شرط کل شیفت: **ورود و خروج هر دو غایب**، `WORKTOTAL=0`، روز کاری غیرتعطیل، وضعیت تعطیلی WebKart معلوم، بدون درخواست قبلی پوشش‌دهنده تاریخ، و بدون مرخصی/مأموریت ثبت‌شده. اگر `WORKTOTAL` مشخص نیست یا مثبت است، ثبت متوقف می‌شود. صفر بودن کسری کار به‌تنهایی مانع پیشنهاد نیست.
- برای روز جاری، حتی اگر هیچ ترددی نیست تا پایان ساعت موظفی پیشنهادی ارائه نمی‌شود. پیش از ثبت هر مورد وضعیت لحظه‌ای از WebKart دوباره دریافت و اعتبارسنجی می‌شود.
- ثبت **فقط با تأیید کاربر** و پس از فعال‌سازی `ENABLE_WRITES=true` انجام می‌شود. در نسخه ارائه‌شده این گزینه همچنان خاموش است و پیکربندی پاسخ `GetPersonIoInfo` هنوز ناشناخته است.

### افزودن تعطیلات رسمی سال‌های بعد

در `holidays.json` به `years` یک آرایه برای سال جدید با تاریخ‌های شمسی `YYYY/MM/DD` اضافه کنید؛ برای مثال:

```json
{
  "years": {
    "1405": ["1405/01/01"],
    "1406": ["1406/01/01", "1406/01/02"]
  },
  "company_closed": ["1405/09/05"]
}
```

مقادیر فوق **فقط مثال ساختاری** هستند و فهرست کامل تعطیلات رسمی نیستند؛ فایل واقعی همراه پروژه تمام ۲۶ تعطیلی ۱۴۰۵ را دارد. برای سال ۱۴۰۶ فهرست رسمی کامل و به‌روز را استفاده کنید. پس از ویرایش، ربات را راه‌اندازی مجدد کنید.
